# Панель управления сайтом

Адрес: `https://soyka.zgo.lt/admin`. Вход по одному паролю.

## Что можно менять

| Раздел | Что там |
|---|---|
| **Альбомы и фото** | Создать, переименовать, скрыть, удалить альбом и изменить его адрес. Порядок альбомов меняется перетаскиванием. Фото загружаются перетаскиванием файлов (JPEG/PNG/WebP до 60 МБ) и при загрузке автоматически уменьшаются до 1600 px, метаданные вместе с GPS удаляются. Порядок фото меняется перетаскиванием. Клик по фото открывает его настройки: описание, перенос в другой альбом, точка обрезки, видимость, карусель, обложка альбома и удаление. |
| **Карусель** | Включить или выключить карусель на главной, задать скорость автопрокрутки (0 - выключена), выбрать фото и порядок слайдов. |
| **Главная и тексты** | Фото главного экрана, слоган, телефон, email, Instagram, Telegram и текст «Обо мне» с наградами. |
| **Цены** | Пакеты: название, цена, пункты и отметка «рекомендуемый». Порядок пакетов меняется перетаскиванием. |
| **Пароль** | Смена пароля: нужно ввести старый. Все остальные устройства после смены разлогиниваются. |

Правки не видны на сайте, пока не нажата кнопка **«Сохранить»** вверху. Загрузка фото - исключение: фото сохраняется на сервере сразу, но в галерее появится, только если альбом и само фото не скрыты. Если открыть админку в двух вкладках и сохранить в одной, вторая откажется сохранять устаревшие данные - страницу нужно обновить.

Удалённые загруженные фото стираются с диска при сохранении, вернуть их нельзя.

## Установка на сервер (один раз)

Сайт больше не статический: nginx проксирует запросы на Node-процесс, который отдаёт страницы и принимает загрузки.

1. Нужен Node.js 22 или новее: `node -v`.
2. Собрать проект:
   ```
   cd ~/trashbin
   git pull
   npm ci
   npm run build
   ```
3. Установить сервис:
   ```
   sudo cp deploy/soyka.service /etc/systemd/system/soyka.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now soyka
   ```
   Проверьте в юните пользователя, пути и `SOYKA_DATA_DIR`: там хранятся загруженные фото, тексты и хэш пароля. Эту папку нужно бэкапить.
4. Узнать первый пароль: при первом запуске он генерируется и один раз печатается в лог.
   ```
   journalctl -u soyka | grep -A1 "Password:"
   ```
   Другой вариант - задать свой пароль до первого запуска через `Environment=SOYKA_ADMIN_PASSWORD=...` в юните.
5. В nginx заменить блок с `root .../dist` на содержимое `deploy/nginx.conf`. Строки `listen`, `server_name` и ssl оставить как есть. Затем выполнить `sudo nginx -t && sudo systemctl reload nginx`.
   Важно: `client_max_body_size` должен быть не меньше 80m, иначе крупные фото не загрузятся. `X-Forwarded-For` нужно перезаписывать, а не дополнять, иначе ограничение на попытки входа можно обойти.

## Обновление сайта

```
cd ~/trashbin && git pull && npm ci && npm run build && sudo systemctl restart soyka
```

Контент и загруженные фото лежат в `SOYKA_DATA_DIR`, а не в репозитории, поэтому обновления кода их не трогают.

## Если забыли пароль

```
cd ~/trashbin
SOYKA_DATA_DIR=/home/myxexe/soyka-data npm run admin:reset-password
```

Скрипт выведет новый случайный пароль. Свой пароль можно передать так: `npm run admin:reset-password -- "мой-новый-пароль"`. Перезапуск не нужен, все старые входы сбрасываются.

После 5 неверных паролей подряд вход с этого IP блокируется на 15 минут.
